# Atlas v4.9.1 种子用户验证策略（Product Freeze）

> 版本：v4.9.1 · Seed User Validation Sprint
> 阶段定位：从「技术验证」进入「产品验证」
> 核心：**用 14 天、50–100 名真实用户证明 Atlas 是否有真实用户价值**

---

## 一、一句话定位

**Atlas 帮购彩者管好每一注彩票：自动兑奖、开奖提醒、资产复盘。**
本 Sprint 不做新功能，只回答一个问题：**真实购彩者是否愿意每周打开 Atlas？**

---

## 二、当前基线（诚实声明）

| 项 | 状态 |
|----|------|
| 技术能力 | 彩票管理 / 自动兑奖 / 开奖提醒 / 资产中心 / 行为分析 / 健康评分 / 周报 / 实验系统 全部实现 |
| 真实用户 | **REAL USER = 1**（产品负责人本人） |
| P1-P3 实验基础设施 | ✅ REAL/SIM 隔离 · 事件系统 · 漏斗 · 留存 · 2 问反馈问卷 |
| 已验证结论 | **无** —— 首次建档率 / D1 / D7 / 付费意愿全部待真实数据 |

**本 Sprint 一切数据必须标注 REAL / SIMULATION，禁止模拟数据进入真实用户报告。**

---

## 三、目标用户与非目标

### 目标用户（A 类，优先招募）
- 每周购买大乐透 / 双色球的固定购彩者
- 复式 / 胆拖玩家
- 长期购彩但不知道中奖情况的用户
- 希望管理彩票投入、控制预算的用户

### 非目标用户（不作为主要实验对象）
- ❌ 从不买彩票的人
- ❌ 只买过一次彩票的人
- ❌ 号码预测 / 玄学爱好者

> 原因：非目标用户无法验证 Atlas 的核心价值（自动兑奖 + 开奖提醒 + 资产管理）。

---

## 四、实验规模与周期

| 项 | 值 |
|----|-----|
| 周期 | **14 天**（T+0 至 T+13） |
| 最低用户数 | **50 名真实用户**（U0001–U0050） |
| 目标用户数 | 100 名（U0001–U0100） |
| 用户来源（允许） | 朋友测试 / 彩票交流群 / 小范围种子用户 |
| 用户来源（禁止） | 模拟用户 / 自动生成用户 / 压测数据 |
| 所有留存数据必须标记 | `REAL_USER` |

### 用户编号体系（必须建立）
```
U0001, U0002, ..., U0050
```
每个用户必须记录：
- **基础数据**：user_id · 注册时间 · 首次打开时间 · 首次保存彩票时间 · 彩票类型 · 购买频率
- **行为数据**：app_opened · onboarding_start · ticket_saved · reminder_enabled · reminder_clicked · draw_checked · claim_completed · asset_viewed · weekly_report_viewed · premium_view

## 五、北极星指标与护栏

### 北极星：**Weekly Active Lottery Users（WALU）**
定义：一周内完成**任意**以下行为的真实用户数：
> 保存彩票 / 查看开奖 / 查看兑奖 / 查看资产

### 核心实验指标（护栏）
| 指标 | 定义 | 目标 |
|------|------|------|
| 首次建档率 | ticket_saved / first_open | **≥50%** |
| D1 留存 | 首见后第 1 天活跃 | **≥40%** |
| D7 留存 | 首见后第 7 天活跃 | **≥30%** |
| 提醒点击率 | reminder_clicked / reminder_received | **≥30%** |
| 提醒价值 | 收到提醒后：是否打开 / 查看开奖 / 查看兑奖 | 记录并分析 |
| WALU | 本周活跃彩票用户数 | 记录 |

## 七、核心验证价值（重点）

### 价值 1：自动兑奖
验证用户是否认为 **「忘记兑奖」是真问题**。

### 价值 2：开奖提醒
验证用户是否**因为提醒回来**。

> 全国每年彩票弃奖超 5 亿元——「中了但不知道/忘了」是真实痛点。
> Atlas 的价值命题：**让你已经中的奖不被漏掉。**

## 十、红线（本 Sprint 严禁）

- ❌ 新增彩票分析算法 / 号码推荐 / 预测模型 / 复杂 AI 功能
- ❌ 新增研究页面 / 无用户验证模块
- ❌ 为增加测试数量开发功能
- ❌ 把模拟数据写成真实用户数据
- ❌ 把数据源存在称为「实时数据」
- ✅ 所有开发必须服务：**真实用户采集 + 行为验证 + 产品决策**

---

## 十一、执行节奏（强制）

```
P0 产品冻结  →  Phase0 Review → 暂停等 A/B/C
P1 实验准备  →  Phase1 Review → 暂停等 A/B/C
P2 用户采集  →  Phase2 Review → 暂停等 A/B/C
P3 数据分析  →  Phase3 Review → 暂停等 A/B/C
P4 Red Team  →  Phase4 Review → 暂停等 A/B/C
P5 CEO Review → 最终决策 A/B/C
```

**禁止连续自动开发。每阶段必须输出 Phase Product Review 并等待审核。**

---

## 十二、验收与决策标准

### 验收（P5 前必须回答）
1. 有没有 **50 人愿意保存彩票**？（首次建档率 ≥50%）
2. **7 天后还有人回来吗**？（D7 ≥30%）
3. 用户回来是因为 Atlas 吗？（提醒价值 / 问卷归因）
4. 有人愿意付费吗？（Q4 付费意愿分布）

### 最终决策（只能选一个）
| 选项 | 含义 | 下一步 |
|------|------|--------|
| **A 真实价值成立** | 达标 | 云同步 + 手机端 + 商业化测试 |
| **B 需要调整** | 部分达标但定位需修正 | 重新设计用户价值 |
| **C 停止投入** | 数据不达标 | 重新评估项目 |
