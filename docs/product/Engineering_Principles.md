# Atlas 工程执行原则（永久生效）

> 确立于 v3.8.0 产品层之后。所有未来 Sprint 必须遵守。

## 原则

1. **禁止新增无用户入口模块** —— 每个新模块必须被桌面/后端实际调用。
2. **所有功能必须绑定桌面入口** —— 用户能在桌面界面触达。
3. **所有功能必须有真实用户场景** —— 回答"用户是谁/为什么用/入口在哪"。
4. **优先复用已有模块** —— 已有能力能满足就不重复开发。
5. **开发顺序严格 Phase 0→7** —— 不跳 Phase。
6. **每 Phase 必须**：编码 + 测试 + UI 入口 + 用户流程验证 + 发布报告。
7. **禁止生成概念模块** —— 不做纯文档/纯设计无实现。
8. **禁止创建无人调用目录** —— 每个目录必须有调用方。

## 检查方式（实证）

- 每个模块在 `desktop/` 或 `backend/` 有 `import` 引用。
- 每个 UI 页面在导航/主窗口注册。
- 每个功能有测试覆盖。
- 无孤立目录（`grep` 全库 0 引用即违规）。

## 决策层例外

产品决策引擎（product_director / product_value / feedback_intelligence）为内部决策层，
通过「工作台 → 产品概览」暴露入口，供产品所有者查看，不直接面向普通用户。

## 红线

- 不承诺中奖/不诱导。
- 不新增无入口 engine 目录。
- 新功能必须产生用户数据并进入反馈循环。
