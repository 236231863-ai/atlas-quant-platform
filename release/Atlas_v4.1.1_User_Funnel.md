# Atlas v4.1.1 用户漏斗报告

> 阶段2 · 基于真实数据 + 诚实标注 · 2026-08-03

---

## 漏斗模型（用户旅程）

```
打开软件 → 首页 → 保存彩票 → 兑奖 → 报告查看 → 再次打开 → 7天回来
```

## 每步数据

| 步骤 | 完成率 | 流失率 | 数据依据 / 原因 |
|------|--------|--------|----------------|
| 打开软件 | 100%（1907 次启动）| 0% | user_intel 启动事件 |
| 到达首页 | ~15%（访问 Dashboard+数据看板 36/241）| 85% | 用户直接进其他页面 |
| **保存彩票** | **无法测量（无埋点）** | — | 埋点缺失 → 无法统计 |
| **兑奖** | **无法测量（无埋点）** | — | 埋点缺失 |
| **报告查看** | **无法测量（无埋点）** | — | 埋点缺失 |
| 再次打开（2天内）| 100%（测试期内重复启动）| 0% | 测试数据 |
| 7 天回来 | **无法测量（仅 2 天数据）** | — | 数据不足 |

## 关键洞察

1. **核心漏斗（保存→兑奖→报告）完全无法测量** —— 当前埋点只覆盖启动/页面/回测
2. **到达首页仅 15%** → 用户打开后直接进 AI/量化页，首页价值未被利用
3. **无 7 天数据** → 留存无法判断，需持续采集

## 原因分析

| 步骤 | 流失原因（推断）|
|------|----------------|
| 打开→首页 | 首页无「输入号码」强入口，用户凭记忆去 AI 助手 |
| 首页→保存 | 无首次引导，用户不知道要保存 |
| 保存→兑奖 | 兑奖在 AI 助手，路径长 |
| 报告查看 | 报告页与研究页重叠，入口不清 |

## 行动建议

1. **补核心埋点**（保存/兑奖/报告/预算/提醒）→ 否则漏斗永远无法测量
2. 首页加「输入号码」主按钮 → 提高到达首页后的转化
3. 首次引导「保存第一注」→ 打通保存环节
4. 持续采集 7 天 → 才能判断留存

## 诚实结论

> **当前无法证明漏斗效率，因为埋点缺失。已知的是：打开→首页只有 15%，用户打开后无动作即离开。**
> 补埋点是回答留存问题的前提（Bug Repair，非新功能）。
