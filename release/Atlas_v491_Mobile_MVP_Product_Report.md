# Atlas v4.9.1 — Mobile MVP 产品报告（Product Report）

> 阶段：v4.9.1 P3 实现 · 版本：Mobile MVP v0.1（真实用户验证版，非商业版）
> 性质：最低成本验证「手机端彩票资产管理需求」是否成立

---

## 一、产品定位

**一句话**：微信里管好每一注彩票——录票自动查奖、开奖自动提醒、中了就告诉你。

**验证的核心问题**（不是做功能，是证明需求）：
| # | 问题 | 指标 |
|---|------|------|
| 1 | 用户是否愿意保存彩票？ | 首次保存率 ≥50% |
| 2 | 用户是否愿意开启提醒？ | 提醒开启率 ≥50% |
| 3 | 用户开奖是否回来查看？ | 开奖查看率 / D7 ≥30% |
| 4 | 用户是否认为 Atlas 不可替代？ | Q2 不便比例 ≥60% |

### 后端（5 张表 + Repository 层 + API）
| 模块 | 能力 | 状态 |

| users | 微信授权（openid→U编号），编号递增，去重 | ✅ |

| API | 9 个 REST 路由（/api/mobile/v1） | ✅ |

### 埋点（复用 + 扩展）
- 复用 17 事件 + 10 里程碑 + REAL/SIMULATION 隔离
- 新增 **SOURCE_MOBILE**（独立来源，计入真实统计）
- 新增 5 个 mobile 事件：`mobile_opened` / `mobile_ticket_saved` / `mobile_reminder_enabled` / `mobile_draw_viewed` / `mobile_feedback_submitted`

### 提醒（微信订阅消息）
- `WeChatReminderClient`：真实模式走微信 API（appid/secret/template_id），验证模式 mock
- `ReminderDispatcher`：批量下发未发送提醒 → 标记 sent
- 只验证「开奖提醒」一种场景

## 三、用户价值（从产品角度）

| 场景 | 解决 |
|------|------|
| 彩票店买完想记下号码 | 录票页 30 秒录入，纸票丢了有底 |
| 忘了开奖时间 | 开奖提醒微信通知 |
| 中奖不知道 | 自动核对开奖，中奖状态直接显示 |
| 月底不知道花了多少 | 本月统计页（投入/中奖/净额） |

**红线严守**：不推荐号码、不预测开奖、无社区/商城、无复杂后台。所有页面含免责声明。
