# Atlas v4.9 P2 用户体验报告（首次使用体验）

> 阶段：P2 · 目标：新用户 30 秒理解价值 + 3 分钟完成建档
> 性质：体验设计改造 + 引擎验证（真实新用户测试为 P3 目标）

## 一、改造前问题

1. **首次引导第一步展示研究指标**（"频率/冷热号/和值走势"）——新用户第一眼看到的是分析术语，而非"这软件帮我什么"
2. 引导是"分析模式"导向（快速分析/深度回测），不导向建档
3. 引导后跳转 Dashboard/回测/报告，**不是建档入口**
4. 建档入口（工作台手动添加）藏在导航深处，首次用户找不到

## 二、改造后流程

### 首次打开（30 秒价值理解）
```
第1步：🎫 以后不用记彩票开奖时间
       Atlas 帮你：
       · 保存彩票，自动兑奖（买了不会忘，中奖自动发现）
       · 提醒开奖（不用记开奖时间，到点提醒你）
       · 统计购彩资产（花了多少、中了多少、心里有数）
第2步：你常买哪种彩票？→ 大乐透 / 双色球
第3步：现在建档，3 分钟完成 → 进入我的彩票
```

### 首次建档（3 分钟闭环）
```
打开 → 理解价值（30s）→ 工作台 → 输入号码 → 保存
→ "已保护" → 知道下次开奖时间
```

### 号码输入（复用 TicketParser，3 种格式全支持）
| 格式 | 示例 | 支持 |
|------|------|:---:|
| 普通 | `01 05 12 23 31 + 03 09` | ✅ |
| 连续 | `01051223310309` | ✅ |
| 多注 | 换行 / 斜杠 / 分号分隔 | ✅ |

## 三、验证结果

- **引导无研究指标**：三步标题/选项不含"冷热号/和值/频率/回测"（测试断言）
- **建档导向**：第 3 步"现在建档"→ 主窗口跳工作台
- **号码解析**：普通/连续/多注格式测试通过
- **接口兼容**：`purpose/lottery/mode/_go/stack` 保留，v361/v460/v480 onboarding 测试不回归

## 四、已知限制

- 首次体验改造基于**代码检查 + 引擎测试**，尚未经过真实新用户（P3 需 10+ 用户实测）
- onboarding_start/complete/drop 事件已可记录（P1 埋点），等待真实数据
- 建档后"下次开奖时间"依赖数据可靠性（大乐透 OK，双色球为内置）

## 五、UX 改进方向（P3 前）

1. 工作台手动添加面板可默认展开（引导完成即见）
2. 首次建档成功后弹"✅ 已保护 + 下次开奖提醒已开启"确认
3. onboarding 事件接入 P4 仪表盘
