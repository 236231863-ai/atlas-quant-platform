# Atlas v4.9 P1 产品验证报告（User Validation Report）

> 阶段：P1 · 目标：验证四问（安装/建档/回访/付费）的数据采集与计算管道已就绪
> 原则：数据优先于猜测 · 服务 WALU 北极星 · 未新增无验证功能

## 一、Q1-Q4 验证框架

| 问题 | 指标 | 定义 | 目标 |
|------|------|------|------|
| Q1 用户愿意安装？ | 安装完成率 | install 后首次打开 / 安装 | ≥50% |
| Q2 愿意保存第一张票？ | 首次建档率 | ticket_saved / 安装 | **≥50%** |
| Q3 会回来查看？ | D1 / D7 留存 | 首见后 1 / 7 天活跃 | **≥40% / ≥30%** |
| Q4 认为资产管理有价值？ | 付费意愿 | premium_click / premium_view | ≥5% |

## 三、模拟基准对账（合成数据，seed=42，100 用户）

| 指标 | 模拟值 | 目标 | 达成 |
|------|-------:|-----:|:----:|
| 安装完成率 | 83.0% | 50% | ✅ |
| 首次建档率 | 52.0% | 50% | ✅ |
| D1 留存 | 47.0% | 40% | ✅ |
| D7 留存 | 47.0% | 30% | ✅ |
| 提醒点击率 | 18.0% | 30% | ❌（漏斗风险点） |
| 付费意愿 | 25.0% | 5% | ✅ |

> 模拟值证明**管道能正确判定护栏达成与否**；提醒点击率 18% 暴露真实漏斗最薄弱环节——开奖提醒触达。这是 P2/P4 的重点优化对象。

## 四、与 WALU 北极星的关联

- WALU = 每周有彩票行为（ticket_saved / claim_checked / draw_reminder_clicked）的用户数
- 模拟 100 用户中 WALU = 52（即首次建档数，因为保存是最核心的彩票行为）
- 后续真实数据到来后，WALU 是判断产品是否被真实需要的最终标尺
