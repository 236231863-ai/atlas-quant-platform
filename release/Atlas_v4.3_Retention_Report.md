# Atlas v4.3 留存报告（Retention Report）

版本：v4.3.0 · 2026-08-03

## 目标指标（v4.3 任务书）

| 指标 | 定义 | v4.3 状态 |
|------|------|----------|
| 首次使用完成率 | 首次用户完成「保存→兑奖→查看」比例 | 引导 30 秒 + 自动兑奖，机制就绪 |
| 每周打开次数 | 周活跃度 | 开奖提醒（每周 6 次天然召回点）就绪 |
| 自动兑奖覆盖率 | 已开奖票据自动匹配/通知比例 | auto_claim + 事件记录就绪 |
| 票据保存率 | 输入号码后保存为票据比例 | AI 助手保存链路就绪 |
| 用户 7 日留存 | 第 7 天仍活跃 | 待埋点数据 |

## 留存闭环（v4.3 建设的 4 个环）

### 环 1：开奖前召回（P1 真提醒）
- 桌面通知 + 开奖倒计时 + 未开奖票据数
- 用户理由：「今晚开奖，我有票」→ 打开看

### 环 2：开奖后主动服务（P2 自动兑奖）
- 开奖 → 自动匹配 → 通知 → 报告 → 状态流转
- 用户理由：「开奖了，中没中？」→ 自动得到答案

### 环 3：花钱有数（P3 资产中心）
- 累计投入/中奖/净收益/风险等级 + 预算预警
- 用户理由：「我花了多少？有没有超预算？」

### 环 4：使用积累（P4 成长系统）
- 连续使用周数 + 成长等级 + 年度 Atlas Report
- 用户理由：「我的数据在积累」→ 舍不得丢

## 用户为什么每天打开（v4.3 回答）

| 时刻 | 答案 |
|------|------|
| 开奖前 | 桌面提醒「今晚大乐透开奖，你有 N 张待兑」 |
| 开奖后 | 自动兑奖报告「中奖 X 注 ¥Y / 本期未中奖」 |
| 没中奖 | 资产/预算/成长让我看清行为、控制风险 |

## 短板（Red Team 指出）

1. **提醒依赖软件开着**——后台定时通知是下一版本最优先优化
2. **无埋点**——5 项目标指标目前无法用真实数据量化（7 日留存等）

## 结论

v4.3 把留存闭环的**机制**全部搭好（提醒→兑奖→资产→成长），验收标准升级为「用户行为发生」。下一步必须**补埋点采集真实 7 天留存**，验证闭环是否真的让用户每天打开。
