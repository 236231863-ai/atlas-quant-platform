## 二、核心保留区（前 7 项）

**自动兑奖 + 开奖提醒 + 票据管理 + 导入 + 可信数据** 构成产品核心闭环：
```
保存票据 → 官方开奖同步 → 自动对号 → 兑奖通知 → 资产报告
```
这 5 个环节技术全部就绪（✅/◐），是 Atlas 真正的价值内核。**一切优先保护这 5 个环节的可靠性。**

## 三、观察区（8-13 项）

行为分析/健康分/复盘等**分析类功能**：价值主张成立，但无真实用户证明。建议**降为次要**，等核心闭环有真实用户后再验证分析价值。

## 四、冻结/归档列表

| 项目 | 冻结原因 |
|------|---------|
| 量化分析中心（v3.9） | 小众、无使用证据、偏离核心 |
| 产品概览/产品总监面板 | 内部工具，不应在用户 UI |
| 129 个无入口 engine 模块 | 概念/实验代码（agent_market/causal/ecosystem_* 等），占体积与维护 |
| 追号观察（遗漏统计） | 边缘价值，易被误读为选号建议，与红线有张力 |
| OCR（真实图片识别未接） | 当前为文本解析+外部接口，未达"拍照即录"承诺，降级为实验 |

## 五、功能健康度结论

1. **核心闭环（5 环节）技术完成、待真实验证**——这是产品立身之本。
2. **分析层（行为/健康/复盘）功能过剩于用户验证**——8 项分析能力无一项有真实用户证明。
3. **概念层（129 模块）严重过剩**——开发投入与用户价值严重错配。
4. 建议：**冻结 129 模块 + 分析层降级，集中资源把核心闭环做到真实用户可用的可靠状态。**
