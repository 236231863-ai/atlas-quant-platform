# Atlas v4.9 P2 移动端技术可行性报告

> 阶段：P2 · 性质：技术可行性评估（本阶段不开发 App）
> 原则：确定正确架构再开发，禁止无评估直接开工

## 一、现有架构基线（评估依据）

| 组件 | 现状 | 对移动端影响 |
|------|------|-------------|
| 桌面端 | PySide6（Windows） | 不可直接复用，需跨端方案 |
| 后端 | FastAPI + SQLAlchemy（`backend/api`） | **可直接复用**为移动端 API 层 |
| 数据库 | SQLite/Postgres（`backend/database`） | 需要云同步才有移动价值 |
| 数据更新 | `IncrementalUpdater` + `atlas_worker` | 数据逻辑可复用 |
| 用户数据 | 本地 `~/.atlas/`（票据/档案/事件） | **核心难点**：目前纯本地，无账号/云端同步 |
| 提醒 | Windows 计划任务 + 桌面通知 | 需换为移动端推送（APNs/FCM） |

## 二、四个方案九维度评分

评分 1-5（5 最优）。**数据同步**指"票据/档案在手机与桌面间一致性"。

| 项目 | A PWA | B 桌面+云API+Web | C Flutter/RN | D 独立原生 |
|------|:---:|:---:|:---:|:---:|
| 开发成本 | **5**（最省） | 4 | 3 | 2 |
| 上线速度 | **5**（当天可上线） | 4 | 3 | 2 |
| 数据同步 | 2（无后端则靠本地） | **4**（云 API 支撑） | 3 | 3 |
| 推送能力 | 1（PWA 推送弱） | **4**（服务端推送） | 3 | **4** |
| 微信/浏览器访问 | **5**（天然支持） | **5** | 2 | 1 |
| Android | 4 | 4 | **5** | **5** |
| iOS | 3（需 Safari PWA） | 4 | **5** | **5** |
| 后续商业化 | 3 | **5**（订阅/云端天然） | 4 | 4 |
| 与现有 Atlas 复用 | 4（复用后端） | **5**（后端+数据逻辑全复用） | 2 | 2 |
| **加权总分** | **32** | **39** | 30 | 28 |

## 三、结论：推荐 **方案 B**

> **Windows 桌面端 + 本地/云 API + 手机 Web（渐进升级到 PWA）**

**理由（优先级）：**
1. **最大化复用**：FastAPI 后端、`IncrementalUpdater` 数据逻辑、`TicketParser`、兑奖引擎全部直接复用，开发成本最低
2. **解决核心痛点**：移动端真正的价值是"出门也能查中奖/录票/收提醒"，前提是**云端同步**。方案 B 的云 API 天然支撑，方案 A（纯 PWA）做不到
3. **渐进路径**：先 Web 验证（1-2 周），加 PWA（可安装/离线），需要时再桥接原生推送——不锁死技术栈
4. **红线兼容**：Atlas 红线（禁预测/推荐）是产品层约束，与技术栈无关，方案 B 可完整继承

**不建议的：**
- **方案 A（纯 PWA）**：无云端同步，票据数据只在一台设备，手机端价值大打折扣
- **方案 C/D（Flutter/原生）**：开发成本高、周期长，在"真实用户验证"未完成前过早投入

## 四、前置条件（进入移动端前的必要条件）

| 前置 | 说明 | 对应 P 阶段 |
|------|------|-----------|
| 账号体系 | 用户登录 + 票据云端存储 | v5.x 前置 |
| 云端 API | FastAPI 部署 + 票据 CRUD + 兑奖查询 | 复用现有 backend |
| 数据同步策略 | 冲突解决（桌面/手机双写） | 需设计 |
| 推送 | APNs/FCM 或极光/个推 | 替代桌面通知 |

## 五、建议的移动端路线图

```
P2（当前）：确定方案 B ✓
  ↓
v5.0：云端账号 + 票据同步 API（复用 backend）
  ↓
v5.1：手机 Web 版（读票据/查兑奖/开奖提醒页）
  ↓
v5.2：PWA 化（可安装 + 离线缓存）
  ↓
v6.0：真实用户验证后再评估原生 App
```

## 六、诚实限制

- 本评估基于**现有架构**，未做移动端原型验证
- 云端同步涉及的账号/隐私/合规（彩票数据敏感）需专项设计
- 真实用户价值未验证前，移动端是**增强项**而非**留存解药**（留存核心仍是提醒+兑奖闭环）
