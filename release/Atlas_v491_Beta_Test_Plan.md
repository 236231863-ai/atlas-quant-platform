# Atlas v4.9.1 — Beta 测试计划（Beta Test Plan）

> 阶段：Phase 4.5 真实测试准备 · 状态：✅ 计划冻结，等待部署
> 目标：用真实用户验证「手机端彩票资产管理」需求
> 执行原则：冻结功能开发，只做部署 / Bug 修复 / 数据链路修复

---

## 一、测试阶段总览

| 阶段 | 规模 | 周期 | 目的 |
|------|------|------|------|
| **种子测试** | 10 人 | **7 天** | 验证链路 / 发现阻断问题 / 修 Bug |
| **正式测试** | 50 人 | **14 天** | 采集真实数据，回答产品价值四问 |

> 种子测试先行：10 人验证无阻断问题后，再放大到 50 人。

---

## 二、种子测试（10 人 · 7 天）

### 目的
1. 验证部署链路（后端 / 小程序 / 埋点 / 提醒）真实可用
2. 发现并修复阻断性 Bug（录票失败 / 无法保存 / 崩溃）
3. 校准引导流程（用户是否知道怎么用）

### 招募（A 类用户）
| 渠道 | 人数 |
|------|-----:|
| 朋友 / 同事 | 5 |
| 彩票交流群 | 5 |

### 7 天节奏
| 天 | 动作 | 检查 |
|----|------|------|
| D1 | 10 人进入，录第一张票 | 录票成功率 / 阻断问题 |
| D2 | 收集反馈（录票是否麻烦） | 引导优化点 |
| D3 | 首个开奖日推送 | 提醒触达 |
| D5 | 中期检查 | 留存初值 |
| D7 | **种子评估** | 决定是否进入 50 人 |

### 种子测试通过门槛
- ✅ 录票成功率 ≥80%（10 人中 ≥8 人成功录票）
- ✅ 无阻断性 Bug（崩溃 / 无法保存）
- ✅ 埋点链路正常（事件真实落库）
- ✅ 提醒链路正常（dispatch 发送 + 事件记录）

### 不通过则修复后重测（不进入正式测试）

## 三、正式测试（50 人 · 14 天）

### 招募
| 渠道 | 人数 |
|------|-----:|
| 朋友 / 同事 | 15 |
| 彩票交流群 | 25 |
| 种子用户转介绍 | 10 |

### 用户编号
- 微信授权自动分配 U0001–U0050+（`UserRegistry`）
- 关联 openid，禁止匿名统计

### 14 天节奏
| 天 | 动作 | 检查 |
|----|------|------|
| T+1 | 首批 ≥10 人进入，录票 | 首次保存率初步 |
| T+3 | 累计 ≥30，触达未录票用户 | 建档率 ≥50% |
| T+5 | 首个开奖日推送全量 | 提醒→打开率 |
| T+7 | **D1/D7 + Q2 问卷** | D1≥40% · D7≥30% · Q2≥60% |
| T+10 | 补录流失原因 | 流失分析 |
| T+13 | 数据封板（≥50 用户） | 全量导出 |
| T+14 | 生成验证报告 | 判断 A/B/C |

### 每日记录（产品负责人）
沿用 `DailyExperimentLog`：新增用户 / 首次打开 / 保存票 / 提醒开启 / 开奖查看 / 兑奖 / 资产 / 周报 / 反馈

## 四、数据指标冻结（只采集 6 项）

| 冻结指标 | 事件名 | 采集点 |
|---------|--------|--------|
| 安装完成 | `install_completed` | 首次授权 |
| 打开小程序 | `mobile_opened` | 每次进入 |
| 保存彩票 | `ticket_saved` | 录票成功 |
| 开启提醒 | `reminder_enabled` | 订阅消息授权 |
| 查看开奖 | `draw_viewed` | 查看开奖结果 |
| 提交反馈 | `feedback_submitted` | 反馈问卷 |

> 只采集这 6 项，不采集隐私 / 号码偏好 / 定位等无关数据。

---

## 五、部署清单（产品负责人执行）

| 步骤 | 操作 |
|------|------|
| 1. 启动后端 | uvicorn 运行 FastAPI（见 User Manual） |
| 2. 导入小程序 | 微信开发者工具导入 `mobile_app/` |
| 3. 配置 appid | 注册小程序，替换 `project.config.json` 的 touristappid |
| 4. 配置订阅消息 | 申请「开奖提醒」模板，设置 `WECHAT_TEMPLATE_ID` 等 |
| 5. 分发邀请 | 复制招募话术（Recruitment Kit） |

## 七、红线（测试期间）

- ❌ 不开发新功能 / 不优化 UI
- ❌ 不制造模拟用户数据
- ❌ 不采集 6 项之外的指标
- ❌ 不承诺中奖 / 不提供号码预测

---

## 八、决策门槛（正式测试后）

| 结果 | 结论 |
|------|------|
| 保存率≥50% + D7≥30% + Q2≥60% | 需求成立 → 小程序增强 + 云账户 |
| 任一核心指标未达标 | 需求不成立 → 停止扩展，回归桌面 |
