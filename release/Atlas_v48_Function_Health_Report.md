## 二、应继续投入 / 冻结 / 删除

### ✅ 应继续投入（A 类核心）
1. **claim_center**（自动兑奖）——最高价值，投入可靠性
2. **draw_monitor**（开奖提醒）——真实装机验证 + 去重降噪
3. **data_center_v2**（双色球源接入）——唯一信任短板
4. **ticket_system / import_center**（建档）——冷启动关键

### 🧊 应冻结（C 类 + B 类边缘）
1. ticket_ocr（未接真实识别，降为实验）
2. 量化中心、策略回测（无使用证据）
3. 成长系统（价值弱）
4. 追号观察（与红线张力）
5. behavior_analysis 的新功能开发（已够用，待用户验证）

### 🗑 应删除/归档（D 类）
1. **129 个无入口 engine 模块**——归档，释放维护成本与打包体积
2. 产品概览/产品总监面板——从用户 UI 移除

## 三、功能健康结论

| 指标 | 数值 |
|------|------|
| 核心价值模块（A） | 7 / 161（4%） |
| 辅助模块（B） | 8 / 161（5%） |
| 实验模块（C） | 5 / 161（3%） |
| 无价值模块（D） | 130 / 161（81%） |
| 有用户入口模块 | ~32 / 161（20%） |

**核心判断**：
1. **80% 的代码模块无用户价值**——开发资源严重错配。
2. **真正有价值的是 7 个 A 类模块**，它们构成完整闭环但从未被真实用户验证。
3. **健康策略**：冻结 C/D，聚焦 A 类做可靠性与真实验证，B 类待 A 类有用户后再优化。
