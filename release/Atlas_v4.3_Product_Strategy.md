# Atlas v4.3 产品策略：留存闭环

> P0 产品冻结 · 2026-08-03

---

## 1. 产品定位冻结

> **Atlas = 帮购彩者管理每一注彩票。**

不是数据分析平台，不是号码预测工具。是"每一注彩票的管理者"：
记录、提醒、兑奖、复盘、管钱。

## 2. 核心指标（v4.3 唯一 KPI）

| # | 指标 | 含义 |
|---|------|------|
| 1 | 首次使用完成率 | 新用户 3 步内完成「保存→兑奖」闭环的比例 |
| 2 | 每周打开次数 | 用户每周主动打开 Atlas 的次数 |
| 3 | 自动兑奖覆盖率 | 已开奖票据中被自动匹配并通知的比例 |
| 4 | 票据保存率 | 购彩后保存票据的比例 |
| 5 | 用户 7 日留存 | 第 7 天仍打开的用户比例 |

**不是**功能数量 / 代码量 / 测试数量。

## 3. 验收标准升级：从「页面存在」到「用户行为发生」

本 Sprint 不再接受"页面存在"：

| ❌ 不接受 | ✅ 接受 |
|---------|--------|
| 首页有开奖提醒按钮 | 用户保存彩票后，开奖当天桌面**弹出提醒事件** |
| 有个人报告页面 | 用户开奖后**自动生成**年度累计变化 |
| 有待兑奖列表 | 用户开奖后票据**自动流转**到"已开奖待查看"并通知 |

实现方式：**用户行为事件记录**（保存/提醒弹出/兑奖查看/报告生成），可验证、可统计。

## 4. 用户为什么每天打开 Atlas？

### 4.1 开奖前为什么打开？
- **下一开奖倒计时**（P1）：周六开奖，用户周四想看"我还有 2 天，票在等"。
- **未开奖票据清单**（P2）："我有 3 张在等开奖"是开奖前的回访理由。
- **预算进度**（已有）：本月投入多少，控制购买节奏。

### 4.2 开奖后为什么打开？
- **桌面提醒事件**（P1）：开奖当天主动弹出"你的 3 张大乐透已开奖"。
- **自动兑奖报告**（P2）：打开即见"中没中、中了多少"，无需主动询问。
- **待兑奖状态流转**（P2）：已开奖待查看 → 已查看 → 已兑奖，逐张推进。

### 4.3 没有中奖为什么留下？
- **资产中心的风险展示**（P3）：累计投入 vs 中奖的诚实账本，帮用户看清负期望。
- **成长系统**（P4）：保存/兑奖/报告次数与连续周数——"我在用 Atlas 管理购彩"。
- **年度报告**（P3/P4）：数据是我的资产，年度总结可带走。
- **不诱导**：不承诺中奖，反而提示风险 → 建立信任 → 长期留存。

## 5. v4.3 聚焦（不新增分析功能）

| Phase | 交付 | 指标映射 |
|-------|------|---------|
| P1 真提醒 | 倒计时+事件通知 | 自动兑奖覆盖率 / 每周打开 |
| P2 自动兑奖 | 4 状态流转+待兑奖列表 | 首次使用完成率 / 自动兑奖覆盖率 |
| P3 资产中心 | 资产账本+风险 | 票据保存率 / 7日留存 |
| P4 成长系统 | 使用成长+年度报告 | 每周打开 / 7日留存 |
| P5 首页二版 | 3 秒价值第一屏 | 首次使用完成率 |
| P6 Red Team | 10 用户验证 | 全部 |
| P7 商业化 | 免费/会员分层 | 留存→付费 |

**P0 Review：通过。** 三个"为什么打开"都有对应 Phase 落地，全部以用户行为事件验收。
